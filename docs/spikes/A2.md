# Spike A2: session-mode coverage

**No pass/fail (sets expectations).** Session mode puts a `DynamicsProcessing` EQ on other apps' audio sessions. It reached
every app that plays on a normal session, but **only Spotify announced its session**. Without Shizuku's `dumpsys`,
session mode would have covered 1 of 5 apps. Chrome plays with no session at all, so neither session mode nor full
mode reaches it.

Date: 2026-11-08. Device: Galaxy A55 (SM-A556E), Android 16, One UI 8.5. Code: `spikes/a1/` (`SessionService.kt`,
same throwaway app as A1).

## Method

- A foreground service (`specialUse`) with a dynamically registered receiver for
  `ACTION_OPEN/CLOSE_AUDIO_EFFECT_CONTROL_SESSION`. It also parses `dumpsys audio` through Shizuku every second.
- Every playing media/game/unknown session gets a deliberately obvious "telephone" EQ: `DynamicsProcessing` pre-EQ at
  priority `Int.MAX_VALUE`, bands ≤300 Hz −24 dB, 300 Hz–3 kHz 0 dB, 3–20 kHz −24 dB.
- Claude drove the phone over adb: opened each app, started playback, and read the logs.
- **"Effect active" was checked in `dumpsys media.audio_flinger`, not by ear.** The DynamicsProcessing effect sits in
  the playing session's effect chain on the output thread, with the app's track active in that chain.

## Results

| App | Player type | Announces session (broadcast) | Found via dumpsys | EQ in the session's active output chain |
|---|---|---|---|---|
| YouTube | AudioTrack | no | yes | ✅ |
| Spotify | AAudio | **yes** | yes | ✅ (attached from the broadcast) |
| com.mero (music) | AudioTrack | no | yes | ✅ |
| Instagram (Reels) | AudioTrack | no | yes | ✅ |
| Facebook | AudioTrack | no | yes (paused player) | not re-tested: only friends' stories would play, and viewing them is visible to them |
| Chrome (mp3 URL) | AAudio, **sessionId −1** | no | yes | ❌ impossible: no session to attach to |
| Samsung Internet | – | – | – | not tested: first-run "agree to Terms" screen, left for the owner |

Not reached:
- Hotstar, Samsung Video, Google Photos, X, WhatsApp, Telegram, Discord: either they need a login or local content, or they aren't media players.
- YouTube Music: not installed.

**Chrome in full mode** (A1 path): while Chrome played the same mp3, the playback capture stayed at −999 dBFS for
30 s. Chrome blocks capture (RootlessJamesDSP lists it as unsupported) and has no session, so **no rootless mode
reaches Chrome audio.**

## What this means for the product

1. **Shizuku is what makes session mode useful.** The broadcast covers only apps that announce (Spotify here). The
   `dumpsys` path found every other session. Without Shizuku, Sorus reaches only announcing apps. The onboarding should
   say plainly what Shizuku adds.
2. **Per-app routing, confirmed.**
   - Full mode is preferred, since it has the whole engine.
   - Session mode is the fallback for apps whose audio doesn't reach the capture. Spotify: A1 found its AAudio stream uncapturable at first, while here session mode reached it immediately.
   - Apps neither mode reaches (Chrome, and probably other session-less AAudio apps) get an "unsupported" badge, not a silent failure.
3. **Package names need `<queries>` / `QUERY_ALL_PACKAGES`.** Under Android 11+ package visibility,
   `getNameForUid()` returned null for most uids, so the table shows uids. The product needs a visibility
   declaration to name apps in its UI.
4. **Session-effect ownership.** Both modes use `DynamicsProcessing` on the same sessions (EQ in session mode, the
   −200 dB mute in full mode). Sorus must run exactly one of them per session, and must handle losing control to
   another effects app.
