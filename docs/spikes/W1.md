# Spike W1: unsigned APO loads system-wide

**Verdict: PASS (on the one PC tested).** Windows 11 25H2 loaded an unsigned, self-built APO into `audiodg.exe` and
applied it to all audio on the onboard Realtek speakers. No certificate, no test signing and no Secure Boot changes
were needed. The Windows 10 22H2, USB DAC and Bluetooth rows of the protocol are still open (see below).

Date: 2026-11-08. Code: `spikes/w1/` (throwaway).

## What was built

- `apo.cpp`: a minimal system-effect APO (COM in-proc DLL) that multiplies every float sample by −6 dB. It implements
  `IAudioProcessingObject`, `IAudioProcessingObjectRT`, `IAudioProcessingObjectConfiguration` and `IAudioSystemEffects`,
  and accepts float32 only.
- `meter.cpp`: plays a 1 kHz sine at −12 dBFS peak on one endpoint while recording that endpoint with WASAPI loopback,
  then prints the RMS of channel 0. The first run warms up the endpoint's effects; the scripts average runs 2–4.
- `selftest.cpp`: loads the DLL directly, creates the APO aggregated (as audiodg does), checks interface delegation,
  the gain and object cleanup.
- `install.ps1` / `uninstall.ps1` (admin):
  1. Copy the DLL to `C:\Program Files\Sorus\spike-w1`.
  2. Register the CLSID and `AudioEngine\AudioProcessingObjects` values.
  3. Append the CLSID to the endpoint's composite mode-effect list `FxProperties {d04e05a6-594b-4fb6-a80d-01af5eed7d1d},14`, backing up the original list.
  4. Restart `audiosrv`.
  5. Measure the level.

A later uninstall/measure cycle read −19.34 dBFS. Everything was confirmed removed (registry, files, audiodg modules), and the
volume setting was unchanged. The 1 dB drift comes from the vendor's own Realtek / Sound Research effects, which
restart with `audiosrv`. Measure on/off deltas back-to-back, never against an old baseline.

## Findings that change the product plan

1. **audiodg creates APOs with COM aggregation.** The first build refused aggregation (`CLASS_E_NOAGGREGATION`,
   `0x80040110`), so audiodg loaded the DLL but every stream on the endpoint failed to open: total silence. The product
   APO must support aggregation (a non-delegating inner `IUnknown`) and should ship with the aggregation self-test.
   It also needs a safe failure mode: an APO that fails to load silences the endpoint.
2. **Windows 11 endpoints use composite FX lists** (CAPX properties 13/14/15 = stream/mode/endpoint effect lists,
   `REG_MULTI_SZ`). Appending a CLSID to the mode-effect list (14) works alongside the vendor's own APOs, and the list
   survives an `audiosrv` restart. The M3 installer should append to these lists rather than replace the vendor's APOs.
   It should fall back to the legacy single-CLSID properties (5/6/7) only where the composite ones are absent.
3. **Registry rights:** `FxProperties` grants Administrators (and Users) only `SetValue`/`QueryValues`. PowerShell's
   `Set-ItemProperty` asks for more and fails. Open the key with exactly `SetValue | QueryValues`; no ownership change
   is needed. COM/APO registration under `HKLM\SOFTWARE\Classes` still needs admin, so the installer elevates once.
4. **WASAPI loopback includes mode effects (MFX).** It is a usable measurement tool for W2 and for an automated
   installer self-check.
5. The DLL must live where audiodg's `LocalService` account can read it. `Program Files` works; the user profile does not.
